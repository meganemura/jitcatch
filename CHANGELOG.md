# Changelog

## [Unreleased]

- On a row where head stopped raising the error the test expects (`X expected but nothing was raised.`), the related guess leaves out a changed method whose edit only changes the arguments of a `raise`. Head no longer reaches that method, so the downstream rule picked the wrong one; the pool now holds the code that called it. `context --json` and `run --json` mark such a method with `edits_only_raise`.

## [0.1.0] - 2026-11-13

First release. jitcatch keeps the Ruby tests that pass on the parent of a change and fail on the change, and names the changed method each one reaches. It never calls a model: an agent writes the candidate tests and judges each result.

- `jitcatch context BASE HEAD` prints a short brief of a change: each changed method with its old and new source, its call sites, the entry points that reach it, and the tests that mention it. It also lists changed constants, gems whose locked version changed, and the Rails callbacks, validations, and FactoryBot factories that run a changed method.
- `jitcatch run BASE HEAD TESTS_DIR` runs each candidate Minitest file or RSpec spec on both revisions, each in its own worktree with its own bundle. It reruns to drop flaky tests, removes non-signals such as load errors, timeouts, and signature changes, and reports what is left. Each reported row shows the old and the new result, the changed method it reaches, and a `rerun:` command for that one test.
- `jitcatch assess RUN.json` applies the rules again to a saved run.
- `--json` on every command prints the same result for a program to read.
- Rails apps: candidates can use the app's factories and test database. When base and head would share one test database on a database server, `run` runs one process at a time and says which line of `config/database.yml` to change.
- A symlinked `.rb` file is not indexed, so it no longer shows up under `parse_errors`. git stores a symlink as the path it points at; the target file is indexed on its own.
- A row shows the `got` line of a failed RSpec `be` or `equal`, and the `expected:` and `got:` arguments of an rspec-mocks failure on unexpected arguments, under `assess:` and under a `fail_on_base` row's `base:`.
- An Active Record `scope` is a changed class method (`Post.recent`) when its statement changes, a `delegate` line defines instance methods, and an `enum :status, {...}` value defines its predicate, bang, and two scopes. Each then gets call sites, tests, and an `entrypoints` line, and `run` counts the names as mentions.
- A candidate that fails the same way on every head rerun, with only its message moving (a random id in a printed record), is kept with the tag `message_varies` when base also passes on `--reruns` reruns, instead of turning `flaky`. A flaky row's rerun line says `(same outcome, message differs)` when only the message moved, lists the base reruns, and is cut at 300 characters.
- `dynamic_callers:` no longer lists a call that only sends the name of a controller action in `reachable_from`, such as `cipher.update` next to `ThingsController#update`: the router calls an action, and no code in the app sends its name.
- A FactoryBot factory that builds a Ruby value (`class: Hash`, `Array`, `Struct`, `OpenStruct`, and a few more) is no longer listed under `factories_skipped:`; it builds no class of the app.
- `run --number-database-url` adds each checkout's `TEST_ENV_NUMBER` to the database name in the `DATABASE_URL` that `--env` passes, so base and head get databases of their own, apart from other worktrees' too, without a change to `config/database.yml`. The report names them under `numbered_databases`. The warning for a shared test database is now two lines: what happened, and how to run both sides at once, which names this flag when `--env DATABASE_URL` passes a URL that names a database on a server. A URL that names no database gets the `config/database.yml` line, which then splits it. An SQLite URL at an absolute path gets the advice to give it a relative path, and the flag refuses an SQLite URL with the same advice.
- A timed-out row's `hint:` names a variable that `--env` passed but the environment did not set before the ones jitcatch did not pass.
- A run whose rows found no table, no database, or a timeout on a side, beside rows that failed on base for another reason, exits 3 too, and starts `jitcatch: no row compared base with head (6 of 7 found no table, and 1 failed on base)`. When other rows did compare, the header has a `warning:` line that counts the rows that found no table and says to load the schema, and a `fail_on_base` row whose base found no table has a `hint:` that names base's database.
- A Grape endpoint (`post "/refresh" do ... end` in a class under `Grape::API`) is a changed method named by its verb and path, as `Things#POST /things/refresh`, built from `prefix`, `resource`, `namespace`, `route_param`, and the like. The calls in its block are its calls, and a request a test sends with that verb to a path ending in its segments counts as a mention, so request specs get `tests:`, `entry_point_tests:`, and `touches:changed_method`. A path built from a string constant the file assigns reads as that string, on both sides; in a test, any other interpolation matches any one segment, or any mount point at the start. The `desc` and `params` before a `route_param` belong to the first endpoint inside it. An endpoint whose path the API class computes any other way is named with that part in braces, matches no request, and gets a `warning:`.
- In a Rails app, `context` and `run` read `config/routes.rb` as source, so a candidate's request to a path helper (`post things_path`, `patch thing_url(thing)`) or to a path counts as a mention of the controller action that serves it. Helpers and controllers take the names of Active Support's inflections and of the literal calls in `config/initializers/inflections.rb` (`person_path` for `resources :people`, `news_index_path` for `resources :news`, `APIKeysController` with an `API` acronym), and `scope module:`, `scope as:`, `scope controller:`, `resources ... module:`, `resources ... as:`, and a verb's `controller:` and `action:` count. A changed controller action's `tests:` lists the files whose requests reach it and the controller tests that call it as `post :create`, with what each sends, in place of a grep of its name. A helper the file does not draw statically gets a `warning:`.
- A change to `db/schema.rb`, `db/structure.sql`, or `db/migrate/` gets a `warning:` in `context` and `run`, which says to load each side's schema into its own test database when the test helper does not call `maintain_test_schema!`, naming the numbered databases. The warning suggests `--setup 'bin/rails db:create db:schema:load'`, which also makes a numbered database that does not exist yet. `run --setup CMD` runs a command once in each checkout before the candidates, with that side's `TEST_ENV_NUMBER`, `DATABASE_URL`, and `RAILS_ENV=test`, so each side's database can hold that side's schema; a failed one exits 3. In a Rails app, a reported row whose head answered 500 names `log/test.log` in its hint.
- A timeout on head alone, beside a base that passed in at most half of `--timeout`, is reported with the tag `head_only_timeout` instead of `discard:timeout`, and does not count toward `untested`: head may loop or wait forever, as a wait that checks a frozen clock does. Its hint gives the time base took, and so does the hint of a head timeout beside a slower base.
- With `--env`, a `rerun env:` line under each `rerun:` line names the variables the line reads from your shell and the ones the run did not have set. It prints no value, because a `DATABASE_URL` can hold a password.
- A row whose side found no table (an `ActiveRecord::StatementInvalid` from `PG::UndefinedTable`, MySQL's `Table '...' doesn't exist`, or SQLite's `no such table` or `Could not find table`) checked nothing, as a database `db:create` made and nothing filled. A candidate whose head found none is `discard:no_table`, and a run whose every row found none on a side exits 3 with a second line that says to run again with `--setup 'bin/rails db:create db:schema:load'`, naming the `--number-database-url` databases. The Rails setup in the README and the skill uses `db:prepare` in place of `db:create` for an app whose test helper does not call `ActiveRecord::Migration.maintain_test_schema!`.
- A `related guess:` line names each changed method by its name and id. With no pick it says that no frame of head's failure is in a changed method and ends with the next step, a `git diff --stat BASE HEAD` that also lists files with no method, such as a view.
- A candidate whose own call no longer fits head (a removed method, new parameters, or a `Data` or `Struct` class whose members changed) gets a `candidate is out of date with head:` line naming what changed and the call to update, and `out_of_date` in `--json`. A call the test writes to `new` of such a class, as `missing keyword: :media`, is now `discard:signature_change` and no longer reported.
- A `--setup` or a load failure whose database refused the connection names the database variables (`DATABASE_URL`, `DB_*`, `PG*`, `MYSQL_*`) the shell sets and `--env` did not pass, with the flags to add.
- `--env NAME=VALUE` names the shell form to use (`export NAME=<value>`, then `--env NAME`), and `env_unset` and `rerun env:` say that the run used the code's own default rather than reading like an error.
- An agent skill in `skills/jitcatch/`.
- Ruby 3.3 or newer. No runtime dependency. On an older Ruby, `jitcatch` exits 1 and names the version it needs and the Ruby it ran on.
- `context` lists, under `readers:`, the code at head that reads each changed value without calling it by name: route helpers that carry a changed `to_param` into a lookup by id, `send` and `public_send` of a literal or a built name, callbacks and validations that name a method, queries under a changed `default_scope`, a constant in SQL text or a query, a validation that reads a constant (looked up as Ruby does, through the enclosing scopes and the ancestors), `create` calls that take a changed column default, `config.` settings, `render json:`, and `to_s` in a page. Each row has the place as `commit:path:line`, the mechanism, a score, `rank:`, `why:`, `also:`, and `test:`, the check a candidate would make. The 10 highest print with a count of the rest; `--all-readers` prints every one. A `not seen:` line names what the source cannot show. BASE and HEAD are read from git, never the checkout.
- A call in an ERB template is a call site: `callsites:` and `reachable_from` list the template (`app/views/loans/index.html.erb:2`). A bare name in a template reaches only a method of `app/helpers/`. A method with no call site but with readers says `callsites: (none by name; N under readers:)`.
- A changed constant's list of the changed methods that read it is now `read_by:` (`read_by` in `--json`), since `readers:` names the new section.
